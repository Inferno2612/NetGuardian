# NetGuardian (Rust/Tauri)

Переписанная версия старого NetGuardian (Python/PyQt6) на Rust + Tauri 2,
со стеклянным интерфейсом (Acrylic/Mica), без функции аппаратного
отключения интернета, с блокировкой приложений и с блокировкой ссылок
в браузере, пока VPN выключен.

## Текущее состояние

- Блокировка ссылок в браузере **временно отключена в интерфейсе** (блок в
  `ui/index.html` закомментирован; расширение, нативный хост и команды
  `blocked_domains_*` сохранены — для возврата раскомментируйте блок).
- Мониторинг сайтов без ограничения количества; проверки идут параллельно
  (не более 8 одновременно), адреса без схемы получают `https://`.

## Статус: весь функционал реализован

Перенесено из старой версии:
- Трафик по интерфейсам отдельно (не суммарно, чтобы не задваивать счёт
  VPN-туннеля), публичный IP/провайдер, мониторинг до 3 сайтов, конфиг
  в `%APPDATA%\NetGuardian\config.json`, автозапуск через реестр.
- Аппаратное отключение интернета удалено полностью.

Новое:
- Определение статуса VPN по виртуальному адаптеру (Hiddify TUN,
  AmneziaWG, WireGuard и т.п.) с резервной проверкой по публичному IP.
- Стеклянный интерфейс (Acrylic/Mica через `window-vibrancy`).
- **Блокировка приложений без VPN** — простой режим (процесс-вотчер,
  без прав администратора) и надёжный режим (IFEO, через реестр,
  требует прав администратора разово).
- **Блокировка ссылок в браузере без VPN** — расширение для
  Chrome/Edge/Firefox + нативный хост, общающийся с тем же ядром, что
  и десктоп-приложение (`browser-extension/`, `native-host/`).

## ⚠️ Код не скомпилирован — важно понимать перед тем, как собирать

Весь код написан и проверен на глаз в Linux-песочнице без доступа к
Windows, поэтому `cargo build`/`cargo tauri dev` здесь ни разу не
запускался. С первого раза наверняка найдутся ошибки компиляции —
особенно в местах с прямыми вызовами Windows API (`core/src/vpn.rs`,
`core/src/elevation.rs`) и версиях Tauri-плагинов, которые могли
измениться с момента моего обучения. **Это нормально для нового
Rust-проекта** — просто присылайте мне текст ошибок целиком, я быстро
поправлю. Самая рискованная и наименее проверенная часть — режим IFEO
(см. предупреждение ниже).

## ⚠️ IFEO-режим блокировки приложений — наименее проверенная часть

Надёжный режим блокировки приложений (`core/src/ifeo.rs`) переписывает
системный реестр (`Image File Execution Options`) и перехватывает
запуск указанного .exe на уровне всей Windows, а не только внутри
NetGuardian. Протестировать это здесь физически нельзя. Логика
продумана внимательно (маркер в реестре, чтобы не удалить чужую запись
Debugger; проверка прав администратора), но **включайте его сначала на
некритичном тестовом приложении**. Если что-то пойдёт не так — вручную
удалите подключ с именем нужного .exe в
`HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options`
через `regedit`.

## Как работает простая блокировка приложений и диагностика

Вотчер раз в секунду ищет процессы из списка и завершает их **вместе со
всем деревом дочерних процессов** (у Electron-приложений — Claude, Discord,
Slack, VS Code — это рендереры, GPU-процессы и т.п., часто с другими
именами .exe). Блокировка никогда не приостанавливается; от спама
защищено только окно-уведомление (не чаще раза в 15 секунд на приложение).
Не трогаются: сам NetGuardian, его родительские процессы и системные
процессы (explorer.exe, svchost.exe и т.п.).

Каждое срабатывание пишется в `%APPDATA%\NetGuardian\blocker.log`:
сколько процессов найдено, сколько завершено и сколько не удалось. Если
«не удалось» > 0 — скорее всего, блокируемое приложение запущено от имени
администратора, а NetGuardian — нет; запустите NetGuardian от администратора
или включите надёжный режим (IFEO).

## IFEO и многопроцессные приложения (Electron/Chromium)

Discord, Claude, Slack и т.п. запускают множество дочерних процессов с
особой передачей дескрипторов; перезапуск каждого через IFEO-заглушку их
ломает. Поэтому NetGuardian (запущенный от администратора) держит
IFEO-перехват активным **только пока VPN выключен**, а при включённом VPN
временно снимает значение Debugger (`suspend_guard`) и возвращает его при
отключении VPN. Без прав администратора эта синхронизация невозможна —
для таких приложений лучше использовать простой режим.

## Требования для сборки на вашем ПК (Windows 10/11)

1. **Rust**: https://rustup.rs
2. **Visual Studio Build Tools** (компонент "Desktop development with C++"):
   https://visualstudio.microsoft.com/visual-cpp-build-tools/
3. **WebView2** — на Windows 11 уже встроен; на Windows 10 ставится
   автоматически при первом запуске, либо отдельно с сайта Microsoft.
4. **Tauri CLI**:
   ```powershell
   cargo install tauri-cli --version "^2"
   ```
   Если на этом шаге `link.exe` падает с ошибкой вроде
   `necessary component may be missing from the "C++ build tools" workload` —
   Build Tools ещё не полностью установлены или не подхвачены.
   Дождитесь «Установка завершена», закройте и заново откройте
   PowerShell, повторите команду.

## Запуск в режиме разработки

```powershell
cd C:\projects\WI-Fi
cargo tauri dev
```

Запускает только десктоп-приложение (`src-tauri`). Браузерное
расширение и нативный хост настраиваются отдельно — см.
`browser-extension/README.md`.

## Сборка релизных файлов

```powershell
cargo tauri build
```

Установщик (.exe, NSIS) появится в
`src-tauri\target\release\bundle\nsis\`.

Для блокировки ссылок в браузере дополнительно соберите нативный хост
и настройте его (подробности — `browser-extension/README.md`):

```powershell
cargo build --release -p netguardian-native-host
.\install-native-host.ps1 -ChromeExtensionId "..."
```

## Структура проекта (Cargo workspace из трёх крейтов)

```
Cargo.toml              — корень workspace, общие версии зависимостей
core/                    — netguardian-core: вся логика без привязки к Tauri
  src/
    config.rs             — настройки в %APPDATA%\NetGuardian\config.json
    vpn.rs                 — определение VPN (адаптер / публичный IP)
    traffic.rs              — счётчики трафика по интерфейсам
    ip_info.rs                — публичный IP/провайдер (ip-api.com)
    sites.rs                   — мониторинг до 3 сайтов
    autostart.rs                 — автозапуск через реестр HKCU\...\Run
    elevation.rs                   — проверка/запрос прав администратора
    ifeo.rs                          — IFEO-перехват запуска приложений
src-tauri/               — десктоп-приложение (GUI)
  src/
    main.rs                — точка входа, Tauri-команды, инициализация окна
    app_blocking.rs          — простой режим блокировки (процесс-вотчер) + окно-уведомление
  capabilities/default.json  — разрешения JS (закрытие окна, события)
  tauri.conf.json           — конфигурация окна, CSP, бандла
  icons/                      — плейсхолдер-иконки (замените на свои)
native-host/              — консольный .exe для Native Messaging браузеров
ui/                       — интерфейс десктоп-приложения (HTML/CSS/JS)
browser-extension/        — расширение браузера + инструкция по установке
install-native-host.ps1   — регистрирует нативный хост в Chrome/Edge/Firefox
```

Зачем общий крейт `core`: и десктоп-приложение, и расширение браузера
должны видеть **один и тот же** статус VPN. Если бы логика определения
VPN была продублирована в двух местах, они могли бы разойтись
(например, после правки списка `vpn_adapter_hints` в одном месте и
забытой в другом) — тогда десктоп показывал бы «VPN включён», а
браузер при этом блокировал бы сайты, или наоборот.

## Про определение VPN

Hiddify в режиме TUN и Amnezia (AmneziaWG) оба создают отдельный
виртуальный сетевой адаптер — именно по нему определяется статус
подключения (`core/src/vpn.rs`, функция `find_vpn_adapter`). Подстроки
для поиска адаптера — в конфиге (`vpn_adapter_hints`, по умолчанию:
wintun, wireguard, amneziawg, hiddify, sing-box, tun, tap). Если ваш
адаптер определится неправильно — посмотрите его настоящее имя во
вкладке **Настройки → «Показать найденные сетевые адаптеры»** и
пришлите мне, я поправлю подстроку.

## Про трафик по интерфейсам (отличие от старой версии)

Старая версия через `psutil.net_io_counters()` суммировала **все**
адаптеры разом. При включённом VPN один и тот же пользовательский
трафик считается дважды: как исходный пакет на виртуальном адаптере и
как уже зашифрованный пакет на физическом (Wi-Fi/Ethernet). Новая
версия считает трафик **по каждому интерфейсу отдельно** — на
дашборде можно выбрать нужный адаптер в выпадающем списке.
